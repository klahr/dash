Why

One agent at a time is the new bottleneck.

Claude Code writes code faster than you can. Then you wait: one terminal, one task, one branch. If you run more, you juggle branches, untangle conflicts and stop trusting your main branch.

How it works

You write the tasks. Claude does them. You decide what lands.

  1. Queue

    Write what you want, as you would in a chat. Queue as many tasks as you like.

  2. Claude works

    Each task gets its own branch and worktree. Your test command checks the result before you see it.

  3. Review

    Read the diff, click through the live preview, or draw on it and send it back.

  4. Approve

    {{.Name}} merges approved tasks one at a time, once the tests pass on the merged code. Or it opens a pull request.

Productivity

Your job becomes deciding, not typing.

  • Stop waiting. Parallel tasks mean there's always a finished diff ready for you.
  • Stop merging by hand. The merge queue brings in the default branch, sends conflicts back to Claude, and closes duplicate work as "already on main".
  • Review in minutes. Diff, test results and a running app on one screen. Rework… continues the same Claude session, so nothing starts over.
  • Upkeep runs on its own. Scheduled scans for security, test gaps, docs drift and dead code fill your issue list. Turn an issue into a task with one click.

Hand over bigger work.

Give a goal like "checkout in under 2 seconds". A coordinator plans the tasks, dispatches them and reviews them within a budget you set.

Unblock from anywhere.

Approve a fix or answer a permission prompt from your phone, so a run doesn't stall.

Safe by default

Fast, not reckless.

  • A person decides what merges. Goals never approve or merge, and every task waits for your Approve unless you turn on automatic approval for its project.
  • Tests guard main. A red build goes back to Claude, not onto your branch.
  • Your code stays home. Runners work on your computers and connect out over HTTPS. Nothing listens on your network.
  • Sandboxed runs if you want them, two-factor sign-in that owners can require, and usage budgets on goals.

FAQ

Questions

Doesn't Claude Code already do this?

Claude Code runs one session. {{.Name}} adds parallel runs, isolated worktrees, a merge queue, a review screen and a board the team can see.

Will AI merge broken code into main?

No. By default every merge needs a person's approval, and the tests check the merged code before it lands.

Do I need an API key?

No. Runners use the Claude Code or Codex login you already have. You don't get a second bill for the model.

Where does my code go?

It stays on your runners. It leaves only when you push.

Can I leave?

Yes. It's AGPL-licensed, your work is ordinary git commits, and deploys use your own scripts.
