Why

One agent at a time is the new bottleneck.

Claude Code writes code faster than you can. Then you wait: one terminal, one task, one branch. Run more by hand and you juggle branches, untangle conflicts and stop trusting your main branch.

Without {{.Name}}

  • You wait for one agent to finish
  • You check out branches to see a change
  • You resolve conflicts by hand
  • "Is it done yet?"

With {{.Name}}

  • Tasks run side by side while you do something else
  • A live preview opens next to the diff
  • The merge queue lands approved tasks in order, and Claude fixes the conflicts
  • The board shows it, on your desk, your phone or the office TV

How it works

You write the tasks. Claude does them. You decide what lands.

  1. Queue

    Write what you want, as you would in a chat. Queue as many tasks as you like; each runner slot takes the next one.

  2. Claude works

    Each task gets its own branch and worktree. Your test command, if you set one, checks the result before you see it.

  3. Review

    Read the diff, click through the live preview, or draw on it and send it back.

  4. Approve

    {{.Name}} merges approved tasks through the merge queue, once the tests pass on the merged code. Or it opens a pull request.

Productivity

Your job becomes deciding, not typing.

The waiting, the merging and the upkeep move off your plate. What's left is the part that needs you.

Stop waiting

Tasks run in parallel, so there's usually a finished diff ready for you.

Stop merging by hand

The merge queue brings in the default branch, sends conflicts and red tests back to Claude, and closes work that's already on main.

Review in minutes

Diff, test results and a running app on one screen. Rework… continues the same Claude session, so nothing starts over.

Upkeep on a schedule

Scans for security, test gaps, docs drift, dead code and more run on a schedule. Each finding becomes a draft task on the board.

Hand over bigger work.

Give a goal like "checkout in under 2 seconds". A coordinator plans the tasks, dispatches them and reviews what each one did, within a budget you set.

Unblock from anywhere.

Approve a fix or answer a permission prompt from your phone, so a run doesn't stall while you're away from your desk.

Safe by default

Fast, not reckless.

Parallel work only helps if you can trust what lands. {{.Name}} keeps a person and your tests in the loop.

  • A person decides what merges. Goals never approve or merge, and every task waits for your Approve unless you turn on automatic approval for its project.
  • Tests guard main. A red build goes back to Claude, not onto your branch.
  • Your repositories stay home. Runners work on your computers and connect out over HTTPS. Nothing listens on your network.
  • Sandboxed runs on Linux and macOS with a bundled script, two-factor sign-in that owners can require, and usage budgets on goals.

FAQ

Questions

Doesn't Claude Code already do this?

Claude Code runs one session. {{.Name}} adds parallel runs, isolated worktrees, a merge queue, a review screen and a board the team can see.

How many tasks run at once?

As many as your runners have slots. Add a computer, or give a runner more slots, to run more. A project can set its own limit, and the queue pauses when your Claude usage window runs out.

Will AI merge broken code into main?

No. By default every merge needs a person's approval, and the tests check the merged code before it lands.

Do I need an API key?

No. A runner on your computer uses the Claude Code or Codex login you already have, so you don't get a second bill for the model. Only a runner the whole team shares needs an API key.

Where does my code go?

Your repositories and checkouts stay on your runners. The hub shows the diffs, logs and previews they send it and keeps the run logs, but never stores your repositories. Claude Code sends code to Anthropic under your own account.

Can I leave?

Yes. It's AGPL-licensed, your work is ordinary git commits, and deploys use your own scripts.
