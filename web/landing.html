How it works

You write the tasks. Claude does them. You decide what lands.

Every task gets its own branch and worktree, so agents never step on each other, and nothing reaches your main branch without your approval.

  1. Queue tasks

    Describe what you want as you would in a chat. Queue as many as you like; they run in parallel, in priority order. A follow-up can continue an earlier task's Claude session.

  2. Claude works in a worktree

    Follow along live and answer permission prompts. When Claude is done, your test command checks the work before it reaches you.

  3. Review the diff

    Read the changes, open a live preview of the app, or send it back with a note. Rework continues the same Claude session.

  4. Approve and merge

    Approved work lands one task at a time, as a squashed commit on your default branch once its tests pass again. Or each task becomes a GitHub pull request, reviewed and merged on GitHub by a person.

Goals

Hand over something bigger than one task.

Say what you want done, such as "checkout in under 2 seconds". A coordinator (Claude) reads the code, plans the tasks, dispatches them and reviews each one. It never approves or merges: that stays yours.

  • You approve the plan. By default it waits for you: edit it, ask for another, or queue it.
  • It stays in budget: the most tasks it may make, and a share of the week's Claude usage.
  • It wakes when a task changes, in review, failed or merged, and can send work back with notes. Its log says what it did and why.

Anywhere

Keep the work moving from your phone.

The same board works on a small screen and installs as an app. Queue the next task from the sofa, approve a fix on the train.

  • Review and approve diffs, test results and live previews.
  • Answer Claude when it asks for permission, so a run doesn't stall.
  • Get notified with push notifications in the browser or the installed app, or webhooks to Slack and ntfy.

Runners

Your machine, your Claude subscription, no open ports

{{.Name}} is the board. The work happens on computers you choose, called runners: your laptop, a desktop at home, a build server. They run on Linux, macOS and Windows.

Your machine

Tasks run where your code already is, with your tools, your repositories and your git credentials. Code doesn't leave the runner unless you push it.

Your Claude subscription

Runners use the Claude Code you've already logged in to. No API keys to hand over and no second bill for the model.

No open ports

A runner connects out to {{.Name}} over HTTPS, like a GitHub self-hosted runner. Nothing listens on your network, and you can revoke it any time.

# on the computer that should run tasks, with the command from the Runners page
$ curl -fsSL {{.Origin}}/runner/install.sh | sh -s -- --code …

Runners can update themselves when the hub is upgraded, and warn you before their disk fills up. Tasks on a project's runners share notes with each other, encrypted end to end.

Also in the box

The rest of the loop

The things around the code that make running many agents at once practical.

Live previews

Each task's app runs on its own address. Click through a change, draw on it, and send the marked-up picture back to Claude as rework notes.

Tests before merge

Your test command checks every result, and runs again in the task's worktree before it merges. A red build goes back to Claude, not onto your main branch.

Merge queue or pull requests

Merge locally, one squashed commit at a time, or open a pull request per task. Claude fixes what GitHub reviewers ask for and replies in their threads; a person merges.

Chat

A general chat, one per project and one per task, with a suggested next reply. Start a message with ! to run a shell command in the project or the task's worktree.

Usage pacing

Meters show each Claude usage window and the time until it resets. Follow the weekly pace per Claude account, or Start now for a task that can't wait. Each run shows its tokens.

Wall view

A full-screen dashboard for the office TV: what runs, what needs a person and today's merges. A TV opens it with a link, without signing in.

Checklist

The repository's TODO.md as a list to tick off, edit and reorder. Move an item onto the board as a task.

Scans and issues

Scheduled read-only reviews fill a project's issue list. Turn any issue into a task with one click.

Use it from Claude

An MCP server, and a custom connector for claude.ai and the Claude app, to create and follow tasks from a conversation.
